# 0008. Logo and favicon assets built from the font and the original lambda

Date: 2026-10-10

## Status

Accepted

## Context

The logo is the symbol `{λ}` followed by the wordmark `asymptora`, set in JetBrains
Mono with no look-alike fallback (RFC 0002, D1). The λ is the brand's own shape;
the braces and the wordmark are letters of the font.

The first attempts to obtain the λ by tracing a raster image produced a wrong
shape (a caret, or the plain symbol without its detail). A traced path also has
no source to compare against, so a later redraw could drift unnoticed.

Two further facts shaped the decision:

- PNG and ICO files are produced by rendering the SVG with cairo. The bytes of a
  raster are not guaranteed to be identical across cairo versions.
- SVG and PNG files produced in some authoring environments were found to gain a
  C2PA provenance block (about 7.7 KB per SVG) that the scripts do not write.
  It appeared between turns of the same session.

## Decision

The logo and favicon files are generated by two scripts under `design/build/`,
run by hand, and their outputs are committed (RFC 0002, D3 and D15).

- The λ path is a constant in `build_logo.py`, copied byte for byte from the
  Design System and never redrawn.
- The braces and the wordmark are glyph outlines read from the official
  JetBrains Mono TTFs with fontTools, pinned to commit
  `19371302b95d218af43299bce79ddbddd0bc364d` (the same 2.305 version the site
  serves). Preset P3 is used: braces in Bold, wordmark in ExtraBold.
- `build_favicon.py` places the symbol on a `surface-page` tile and writes
  `favicon.svg`, `favicon.ico` (16, 32 and 48 px) and `apple-touch-icon.png`
  (180 px). The tile exists because `ink` against a light browser tab has a
  contrast of about 1.14:1.
- Both scripts are deterministic and `build_favicon.py` ignores any `<metadata>`
  block in its input.
- The scripts use Python (fontTools, cairosvg, pinned in `requirements.txt`),
  while the rest of the repository is Node. CI does not run them. It runs
  `design/build/check-assets.mjs`, which checks structure only: the λ path in the
  logo files, the ICO entries, the Apple icon size, and no `<metadata>` block or
  C2PA marker in any SVG, PNG or ICO under `public/`.

## Alternatives considered

| Alternative | Why it was not chosen |
|---|---|
| Trace the λ from a raster | Already tried; it gave a wrong shape and leaves nothing to compare against |
| Wordmark as live text in the SVG | It would depend on the font loading, with a fallback face in its place while it does not. RFC 0002, D1 rules out a look-alike fallback in the logo |
| Run the Python scripts in CI and fail on a diff | Needs Python and cairo in CI, and the raster bytes are not stable across cairo versions, so the diff would fail for reasons unrelated to the logo |

## Consequences

The SVG outputs are reproducible: running the scripts again gives the same bytes,
and `design/build/README.md` records their SHA-256. The PNG and ICO are not
compared by hash; if someone regenerates them with another cairo version, the
picture is compared, not the bytes.

CI cannot tell whether the logo was generated by the script or edited by hand,
only that its structure is valid. The protection is the rule in
`design/build/README.md` (never edit a generated file) and review. This is a
weaker guarantee than the token stylesheet has (ADR 0006), and it is accepted.

The λ path appears in two places that must agree: `build_logo.py` and
`check-assets.mjs`. A change of the logo means the Design System changes first,
then the constant in both files, then the outputs are regenerated.

The repository needs Python 3.13 and cairo 1.18 only to regenerate the logo,
which happens when the logo or the font changes. The regeneration procedure is in
[the runbook](../../runbooks/regenerate-visual-assets.md).
